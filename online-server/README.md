# Сервис Why client r7

Node.js считает онлайн и передаёт косметические эффекты между клиентами. Официальный клиент r7 сразу использует **https://why-client.onrender.com**; смена адреса в интерфейсе и конфиге закрыта. Сам Minecraft сервер остаётся отдельной программой.

## Запуск

Node.js 22+, внешних npm-зависимостей нет:

```sh
npm test
node server.mjs
```

По умолчанию PORT=8080 и HOST=0.0.0.0. Dockerfile готов. Для Render корневая папка сервиса должна быть `online-server`, поскольку Dockerfile находится там. Обновляй сервис из этой папки и сохраняй существующий адрес why-client.onrender.com.

`GET /health` возвращает `{"ok":true}`. HTTPS адрес клиента указывается без /health. Холодный запуск бесплатного сервиса может задержать первый ответ.

## Клиенты

Оба игрока используют r7, один адрес подключения Minecraft и одно измерение. Главное меню → адрес слева сверху: статус и переключатель общих эффектов. Другой клиент принимает эффекты даже с выключенными собственными визуальными модулями.

Настройки `.minecraft/config/whyclient-online.json`:

```json
{"endpoint":"https://why-client.onrender.com","enabled":true,"effects":true}
```

В r7 endpoint игнорируется и заменяется постоянным адресом из кода. enabled:false выключает онлайн целиком; effects:false — отправку/получение визуалов. Местные эффекты и Fake Player работают без сети.

## Совместимость r6/r7

Добавлен опциональный проверяемый `state.wings`: размер, взмах, размах, свечение, прозрачность и два цвета. Старые r6 состояния принимаются без него. Старый backend продолжит передавать остальные эффекты, но отбрасывает неизвестные крылья; обнови relay для их передачи.

Смерти используют совместимое событие death style=0: amount=1 — электризация, 2 — чёрная дыра, 3 — вознесение. r7 декодирует все варианты; r6 отображает прежний вариант. HTTP API сохранён.

## Обмен и ограничения

GET /v1/online и POST /v1/presence — счётчик активных сессий с визуалами. Heartbeat каждые 30 секунд, TTL 90 секунд; это не подтверждённые уникальные люди.

POST /v1/visuals/sync — параметры и события. До 4 запросов/сек и 8 событий в запросе. Курсор/номера исключают повторы; state TTL=6 сек, event TTL=3 сек. Задержка учитывается при проигрывании. Комната — SHA-256 адреса игрового сервера и измерение.

UUID владельца/цели, координаты и параметры временно хранятся в памяти. Ник, пароль и токен Minecraft не отправляются. Косметический протокол не авторизует игровые действия. Получатель проверяет сущности текущего мира/дистанцию; погибшее тело скрывается только после подтверждения смерти Minecraft.

Лимиты: 20 000 сессий, 2 000 комнат, 64 сессии/IP, 16 KiB тело запроса, 32 участника/64 события в ответе, 256 событий/комнату. Неизвестные поля не пересылаются. Данные удаляются по TTL/при перезапуске. Один процесс обслуживает общий URL; несколько экземпляров требуют общего хранилища.

TRUST_PROXY=1 допустим только за прокси, заменяющим X-Forwarded-For при закрытом прямом доступе к сервису.

npm test проверяет настоящий HTTP, счётчик/TTL, комнаты, эхо/повторы, старые r6 состояния, параметры крыльев r7, три варианта смерти, числовые границы и ограничения частоты/ёмкости.
