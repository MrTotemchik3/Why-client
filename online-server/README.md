# Сервис Why client r11

Node.js считает онлайн и передаёт косметические эффекты между клиентами. Официальный адрес клиента — **https://why-client.onrender.com**; смена адреса закрыта. Minecraft сервер остаётся отдельной программой.

## Запуск

Node.js 22+, внешних npm-зависимостей нет:

```sh
npm test
node server.mjs
```

PORT=8080, HOST=0.0.0.0 по умолчанию. Dockerfile готов. На Render Root Directory = `online-server`. Сохраняй существующий адрес сервиса. `GET /health` → `{"ok":true}`. Холодный запуск бесплатного сервиса может задержать соединение.

## Что видит другой игрок

Оба игрока устанавливают **r11**, подключаются по одному адресу Minecraft в одном измерении и включают общие эффекты в окне онлайн слева сверху главного меню. Принимаемые эффекты рисуются независимо от локальных переключателей модулей.

Передаются Target ESP/атаки, Die Effect, крылья, Aura, Player Trails с настоящим скином, Custom Model, Cape Physics, Weather Visuals возле владельца, Why Drone и авария, Jump Circle, Footsteps, Effects (стрелы, жемчуг, тотем, портал, взрыв), Block Overlay, Pings, Waypoints и поза Item Inspect. Для общего неба/цветокоррекции используются настройки ближайшего видимого владельца Why shader, если собственный Why shader выключен. Включённый собственный шейдер имеет приоритет. Повторный TNT-взрыв не накладывается на уже созданный локальный эффект Effects.

HUD, меню и Fake Player остаются локальными. Поддельные сущности, ущерб и действия игрового сервера не передаются. Реальная смерть подтверждается Minecraft до скрытия тела. Без Why client эти косметические эффекты не отображаются.

Настройки `.minecraft/config/whyclient-online.json`:

```json
{"endpoint":"https://why-client.onrender.com","enabled":true,"effects":true}
```

endpoint всегда заменяется адресом из кода. enabled:false выключает онлайн; effects:false выключает отправку/приём визуалов. Местные эффекты работают без сети. Метка Why в TAB использует UUID активных участников relay.

## Протокол и совместимость

`POST /v1/visuals/sync`, visualVersion:11: проверяемый `state.world` содержит числовые массивы по `world-schema.json` и максимум 14 коротких меток. Никаких файлов, кода или URL от игроков. Новые `kind:world` события задают позицию и параметры прыжка, следа, тотема, портала, взрыва и привязку снаряда. Старые клиенты получают свои совместимые поля; новые поля/события для них отфильтровываются без изменения состояния владельца.

Target style 0–8, duration до 3000 мс, amount до 9. Для r6/r7 границы ответа ограничены прежними значениями. Смерти: death style=0, amount=1 — электризация, 2 — чёрная дыра, 3 — вознесение, 4 — огромная булава, 5 — белая дыра.

До 4 запросов/сек, 8 событий/запрос. Курсор и ID исключают повторы. Клиент удаляет отправленные события после успешного ответа и устанавливает первое соединение запросом состояния. State TTL=6 сек; события хранятся 3 сек. Комната — SHA-256 адреса Minecraft и измерения. Разные адреса/алиасы создают разные комнаты.

## Ограничения и данные

Лимиты сервиса: 20 000 сессий, 2 000 комнат, 64 сессии/IP, 16 KiB запрос, до 12 участников в ответе r11 (32 для прежних), 64 события, 64 000 байт ответа, 256 событий/комнату. Неизвестные поля удаляются. Рендер клиента ограничен 8 ближайшими загруженными владельцами, 4 владельцами копий по 6 фантомов, 2 погодными пулами, 32 событиями/снарядами и 24 метками на кадр. Это косметические лимиты, не изменение игровых сущностей.

UUID, координаты, параметры и подписанные пользователем названия меток временно хранятся в памяти. Пароли/токены Minecraft не отправляются. TTL/перезапуск удаляет данные. Общий URL обслуживает один процесс; несколько экземпляров требуют общего хранилища.

GET /v1/online и POST /v1/presence: активные сессии, heartbeat 30 сек, TTL 90 сек; не подтверждённые уникальные люди. TRUST_PROXY=1 допустим за прокси, заменяющим X-Forwarded-For и закрывающим прямой доступ.

`npm test`: 9 тестов — настоящий HTTP двух участников, все r11 поля/события, совместимость, выключение состояний, комнаты, эхо/повторы, TTL, границы/маркеры, предел байтов, частота/ёмкость.
