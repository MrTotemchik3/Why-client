# Сервис Why client r6

Один процесс Node.js считает онлайн и передаёт косметические эффекты между клиентами r6. Клиент Minecraft и игровой сервер остаются отдельными программами. Готового публичного адреса в архиве нет.

## Запуск

Node.js 22 или новее, зависимостей npm нет:

```sh
npm test
node server.mjs
```

По умолчанию порт 8080; его задаёт `PORT`, интерфейс — `HOST`. Локальная проверка: `http://127.0.0.1:8080`. В игре открой «Онлайн», укажи адрес, включи «Общие эффекты» и нажми «Сохранить и проверить».

## Подключение других игроков

1. Размести папку `online-server` на постоянном Node.js хостинге или VPS. Dockerfile также готов.
2. Поставь HTTPS-прокси перед портом 8080. Публичный клиент принимает HTTPS; HTTP разрешён только для localhost.
3. Во всех клиентах r6 укажи один публичный URL сервиса, например `https://visuals.your-domain.example` (адрес-пример нужно заменить своим).
4. Оба игрока заходят на один Minecraft сервер с одинаковым адресом подключения и в одно измерение. Для проверки включи Target ESP / Mace Anim на одном клиенте; другой клиент принимает эффекты даже с выключенными собственными модулями.

Конфигурация `.minecraft/config/whyclient-online.json`:

```json
{"endpoint":"https://visuals.your-domain.example","enabled":true,"effects":true}
```

`effects:false` отключает отправку и получение общих эффектов; локальные визуалы и превью остаются. `enabled:false` отключает весь онлайн-сервис. Конфигурация перечитывается каждые 10 секунд. Fake Player локальный и не передаётся другим клиентам.

## Обмен

`GET /health`, `GET /v1/online`, `POST /v1/presence` — счётчик. Анонимный heartbeat раз в 30 секунд, срок сессии 90 секунд; это число активных сессий, а не подтверждённых уникальных людей.

`POST /v1/visuals/sync` — визуалы. Клиент обновляет параметры до четырёх раз в секунду и передаёт до восьми событий в одном запросе. Ответ содержит параметры других участников и короткий журнал новых попаданий/убийств. Курсор и номера событий убирают повторы. Срок параметров 6 секунд; событий 3 секунды; задержка в очереди входит во время анимации. Комната — SHA-256 адреса игрового сервера и измерения, а не общий мировой канал.

UUID участника/цели и координаты событий нужны для сопоставления с игровыми сущностями. Ник, пароль и токен Minecraft не отправляются. Сервис временно хранит эти данные в памяти и не пишет базу данных. Обмен косметический, без проверки аккаунта Minecraft: ему нельзя доверять игровые решения, урон или авторизацию. Получатель сверяет владельца/цель с текущим миром, ограничивает расстояние и запускает исчезновение тела только после смерти, подтверждённой Minecraft.

## Ограничения

До 20 000 сессий, 2 000 комнат, 64 сессии на IP. Тело визуального запроса до 16 KiB; ответ ограничен 32 участниками и 64 событиями; кольцо событий до 256 на комнату. Неизвестные JSON поля не пересылаются. Ограничения частоты, времени запроса, объёма и числа участников защищают процесс от бесконечных очередей. Данные удаляются при истечении TTL и перезапуске.

Один процесс должен обслуживать всех пользователей данного URL. Несколько экземпляров потребуют общего хранилища или маршрутизации на один экземпляр. Для HTTPS-прокси используй `TRUST_PROXY=1` только если прокси заменяет `X-Forwarded-For` и порт сервиса закрыт от прямого внешнего доступа.

Проверки `npm test`: настоящий HTTP, счётчик и TTL, два участника, все три типа событий, отсутствие эха и дублей, разделение комнат, компенсация задержки, ограничения ёмкости/частоты и проверка данных.
